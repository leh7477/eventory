## 3. 조치 내역

### 3.1 개인정보 (문제 1, 2)

**처리방침 페이지 신설** — `/privacy`, 10개 조항
수집항목·목적·보유기간·제3자제공·위탁·권리·파기·안전성조치·보호책임자·변경.
수집 항목은 실제 폼과 일치시켰다. 푸터에 링크.

**동의 체크박스** — 법정 고지 4항목(목적·항목·기간·거부권)을 보여주고 체크를 받는다.
동의 시각·버전을 함께 저장해 입증에 쓴다.

> **확인 중 고친 것:** 푸터의 처리방침 링크가 우하단 떠있는 문의 버튼에 가려
> **클릭이 불가능**했다. 법적으로 항상 닿아야 하는 링크라 왼쪽으로 옮겼다.

검증: 동의 없이 전송 시 차단, 체크 후 정상 접수, 모바일 375px 정상.

### 3.2 접속기록 (문제 4)

nginx 리버스 프록시를 추가해 접속기록을 남긴다.
`/var/log/eventland/access.log`, **13개월 보관**.

> **확인 중 고친 것:** 기본 nginx 규칙이 와일드카드라 이 로그도 **14일 만에 삭제**될
> 상황이었다. 전용 디렉터리로 분리해 해결했다.

somtip.kr(같은 서버 운영 중)에 영향이 없음을 작업 전후로 확인했다.

### 3.3 백업 (문제 5)

`scripts/backup-db.mjs` — Supabase DB 비밀번호 없이 `service_role` 키만으로
전 테이블을 gzip JSON으로 저장. 매일 새벽 4시 cron. 30일 보관, 권한 700.

검증: 15개 테이블 121행 저장 → 압축 해제 후 문의 17건·이력·31개 필드 전부 복원 확인.
비밀번호는 포함되지 않는다(복구 시 재설정 필요).

### 3.4 권한 (문제 6)

미들웨어는 **화면 이동만** 막고, 서버 액션은 로그인 여부만 확인하고 있었다.
권한 없는 직원이 요청을 직접 만들면 통과할 수 있었다.

`requireSection(key)` / `requireAnySection(...keys)` 도입, **56곳 교체**.
견적 화면에서 쓰는 일정 등록은 두 권한 중 하나면 통과하도록 예외 처리.

**검증 (실제 직원 계정으로):**
1. 거래처 권한 부여 → 거래처 추가 **성공**
2. 화면을 연 채로 권한 회수 → 같은 화면에서 재시도 → **차단**, DB 미생성 확인

### 3.5 변경 이력 (문제 8)

`audit_log` 테이블 + `lib/admin/audit.js`.
재고 6곳 · 단가 5곳 · 거래처 3곳에 기록 추가.
문의 행 안(jsonb)이 아닌 **별도 테이블**이라 원본을 지워도 "누가 지웠는지" 남는다.
삭제 시에는 지워지기 전 이름을 확보해 기록한다.

기록 실패가 본래 작업을 막지 않도록 설계했다.
검증: 테이블이 없는 상태에서 거래처 추가가 정상 동작.

### 3.6 그 외

- **로그 무한 증가** → `pm2-logrotate` (10MB 단위, 14개, 압축)
- **비밀번호** 6자 → **10자**
- **마이그레이션 체계** → `supabase/migrations/` 신설
- **문서** → `docs/` 8개 문서

## 4. 남은 일

### 4.1 네가 SQL만 실행하면 되는 것

Supabase 대시보드 → SQL Editor에서 순서대로:

| 파일 | 내용 |
|---|---|
| `20260924-privacy-consent.sql` | 동의 기록 컬럼 — **실행 전까지 동의 시각이 저장되지 않는다** |
| `20260924-audit-log.sql` | 이력 테이블 — 실행 전까지 변경 이력이 쌓이지 않는다 |
| `20260924-vendor-fk.sql` | 거래처 연결 정리 (고아 데이터 해소) |

코드는 이미 배포돼 있고, 테이블이 없어도 화면은 정상 동작한다.

### 4.2 외부 조건이 필요한 것

| 항목 | 필요한 것 |
|---|---|
| **HTTPS** (문제 3) | 도메인 구매 → Cloudflare 연결 → nginx 인증서. **nginx는 준비 완료** |
| 스팸 차단 (문제 10) | Cloudflare 봇 차단 |
| 개발 DB 분리 (문제 7) | Supabase 프로젝트 추가 생성 (무료 2개까지) |
| 처리방침 실제 정보 | 대표자·주소·연락처·보호책임자 |

### 4.3 처리방침의 임시값 — 오픈 전 필수

| 위치 | 현재 | 필요 |
|---|---|---|
| `lib/privacy.js` `PRIVACY_OFFICER` | `(담당자명)` `(직책)` | 개인정보 보호책임자 |
| `lib/constants.js` `SITE.ceo` | `홍길동` | 실제 대표자 |
| `lib/constants.js` `SITE.address` | `테헤란로 00, 0층` | 실제 주소 |
| `lib/constants.js` `SITE.phone` | `010-0000-0000` | 실제 번호 |

**처리방침은 법적 문서다. 임시값 상태로 홍보하면 안 된다.**

### 4.4 확인이 필요한 것

**Supabase 리전** (대시보드 → Settings → General → Region)
국외면 처리방침에 **국외이전 고지**를 추가해야 한다 (제28조의8).

### 4.5 여유 될 때

- 정산 컬럼 10개 → 별도 테이블 (`inquiries` 가 컬럼 31개로 5가지 역할 겸함)
- 구버전 컬럼 삭제 (`name`, `event_date` — 사용 0건)
- 문의 보유기간 경과분 자동 파기
