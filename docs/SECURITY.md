# 보안 · 개인정보

## 키 관리

| 키 | 위치 | 성격 |
|---|---|---|
| `anon` | 브라우저 노출 | 공개 키. 노출돼도 정상. RLS가 막는다 |
| `service_role` | **서버만** | RLS 우회. 유출되면 전 데이터 열람·변조 가능 |

**`lib/supabase/admin.js` 를 `"use client"` 파일에서 import하면 키가 번들에 실린다.**
빌드 후 검사하는 방법:
```bash
grep -r "$(grep SUPABASE_SERVICE_ROLE_KEY .env.local | cut -d= -f2)" .next/static/
```
아무것도 안 나와야 정상이다. (2026-09-24 검사: 19개 파일 중 0건)

## 권한 3단계

```
1. 미들웨어      화면 이동 차단        middleware.js
2. 서버 액션     요청 자체 차단        requireSection()
3. RLS           DB 접근 차단          Postgres 정책
```

**화면에서 숨기는 것만으로는 안전하지 않다.** 서버 액션마다 권한을 다시 확인한다.

| 함수 | 용도 |
|---|---|
| `requireAdmin()` | 로그인 여부만 |
| `requireSection(key)` | 로그인 + 해당 메뉴 권한 |
| `requireAnySection(...keys)` | 여러 메뉴 중 하나라도 |
| `requireOwner()` | 최고관리자 (계정 관리) |

### 계정
| 등급 | 권한 |
|---|---|
| `owner` | 전 메뉴 + 계정 관리 |
| `staff` | 지정한 메뉴만 |

- `role` 이 없는 시드 계정은 owner로 간주한다
- 비밀번호 10자 이상
- **계정 공유 금지** (누가 했는지 추적 불가능해진다)
- 퇴사 시 당일 삭제

## 개인정보

### 수집
견적 문의 1곳. 항목은 `lib/privacy.js` 의 `COLLECTED_REQUIRED`.
**처리방침 고지 항목과 실제 수집 항목이 항상 같아야 한다.**

### 동의
- 체크 없이는 전송되지 않는다
- 동의 시각·버전을 `inquiries.privacy_agreed_at` / `privacy_version` 에 기록
- 동의문을 고치면 `PRIVACY_VERSION` 을 올린다

### 법적 의무
| 항목 | 근거 | 상태 |
|---|---|---|
| 처리방침 공개 | 제30조 | ✅ `/privacy` |
| 수집·이용 동의 | 제15조 | ✅ 체크박스 |
| 전송 구간 암호화 | 안전성 확보조치 기준 | ❌ **HTTPS 없음** |
| 접속기록 1년 이상 | 동 기준 제8조 | ✅ nginx 13개월 |
| 보유기간 경과 시 파기 | 제21조 | ❌ 자동 삭제 없음 |
| 국외이전 고지 | 제28조의8 | ❓ 리전 확인 필요 |

### 저장 시 암호화
**불필요하다.** 이름·전화·이메일·주소는 암호화 의무 대상이 아니다.
의무 대상은 고유식별정보(주민번호 등)·비밀번호·생체정보인데 수집하지 않는다.

## 로그

- **개인정보를 로그에 남기지 않는다.** (2026-09-24 검사: 전화·이메일 0건)
- 변경 이력은 `audit_log` — 원본을 지워도 "누가 지웠는지" 남는다
- 접속기록은 `/var/log/eventland/access.log`

## 알려진 취약점

| 항목 | 위험 | 대응 |
|---|---|---|
| HTTPS 없음 | 개인정보 평문 전송 | Cloudflare + nginx (도메인 필요) |
| origin 직접 노출 | Cloudflare 우회 가능 | 방화벽에서 Cloudflare IP만 허용 |
| 문의 무제한 등록 | 스팸 | Cloudflare 봇 차단 |
| 개발·운영 DB 동일 | 실수로 실데이터 변경 | Supabase 프로젝트 분리 |

### Cloudflare 적용 시 반드시 함께
origin(`134.185.108.37:3001`)이 열려 있으면 **Cloudflare를 우회할 수 있다.**
방화벽에서 Cloudflare IP 대역만 80/443을 허용해야 실제로 보호된다.

## 사고 시

1. `service_role` 키 유출 의심 → Supabase 대시보드에서 **즉시 재발급**
2. 계정 도용 의심 → 해당 계정 삭제 + 비밀번호 전체 변경
3. 개인정보 유출 확인 → **정보주체에게 통지** + 개인정보보호위원회 신고
   (72시간 내, 제34조)
4. `audit_log` 와 `access.log` 로 경위 파악
